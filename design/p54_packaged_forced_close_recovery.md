# P54 — Packaged forced-close recovery

## Player-facing risk

An interrupted write must not silently replace a usable run or presentation profile with malformed state. The packaged candidate already validates primary and backup candidates; P54 proves that boundary across a real terminated Windows process.

## Harness flow

1. Reuse the clean-install profile and relocated executable.
2. Launch a dedicated preparation phase that loads the known active battle and settings.
3. Flush valid backups, strand malformed primary run/settings files, and publish a readiness sentinel.
4. Terminate the process externally from the lifecycle runner.
5. Relaunch the same packaged executable and profile.
6. Require backup recovery of battle step, UI scale, window preset, and controller remap.
7. Rewrite both primary files at current schemas and include the termination/recovery evidence in packaged smoke schema 3.

## Boundary

This proves one deterministic abrupt-termination fixture. Human testing around varied real OS timing, antivirus interaction, power loss, and storage failure remains pending.
